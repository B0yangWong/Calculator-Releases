# Validation Scope / 验证范围

This document records the checks and boundaries for Calculator 1.1.3 / build 13, completed on 2026-10-15. It is not a proof of correctness for every expression, Mac, or physical model. The [v1.1.3 release notes](https://github.com/B0yangWong/Calculator-Releases/releases/tag/v1.1.3) also record the package checksum and distribution limits.

Only this summary is public. Application source, test source, private histories, and local diagnostic logs are not published.

## Independent Physics Examples

Expected answers are derived from SI definitions, CODATA reference constants, or independently rearranged equations. They are not generated by asking the same calculator for a forward answer and treating its reverse calculation as independent evidence. Checks compare the applicable value, dimensions, unknown name, solution count, and error state.

The examples cover compatible unit conversion, editable constants, forward and reverse solving, multiple roots, no solution, missing information, incompatible dimensions, division by zero, and original-domain exclusions. Representative relations include $E=mc^2$, $F=ma$, $K=mv^2/2$, $PV=nRT$, $E=hf$, and $\lambda=h/p$. These are checked within their stated physical models, not as universal descriptions of every system.

The reference sources are [NIST's 2022 CODATA table](https://physics.nist.gov/cuu/Constants/Table/allascii.txt), [BIPM SI base units](https://www.bipm.org/en/measurement-units/si-base-units), and [BIPM defining constants](https://www.bipm.org/en/measurement-units/si-defining-constants). For example, $c=299\,792\,458\,\mathrm{m/s}$ and $1\,\mathrm{eV}=1.602176634\times10^{-19}\,\mathrm{J}$ use defined values; the fine-structure constant is an adjusted measured value, not an exact constant.

Numeric comparisons in this example set use a relative-error bound of $2\times10^{-12}$, without a blanket absolute tolerance that would treat electron-volt-scale values as zero. Exact zero is checked separately. This is a software comparison rule, not a measurement uncertainty, universal accuracy guarantee, or promise about significant figures.

## Numerical Boundary Regressions

- Supported fractional-index root inversions must retain all real branches that the current solver handles, including negative roots where appropriate.
- A small negative discriminant must not be forced to zero, and distinct roots must not be merged simply because their residuals are small. A bounded decimal-rational check is limited to supported input structures; it is not a general arbitrary-precision engine.
- Input rounding, underflow, coefficient cancellation, and ill-conditioned root classification must not silently certify an exact root or prove no solution. The safe outcome outside the reliable range is an explicit refusal to solve.
- Original numeric text is retained before parsing and while converting pasted input to editable math. Boundary regressions include the ASCII-to-LaTeX-to-MathLive-ASCII path, so decimal digits cannot disappear before the precision guard sees them.
- Candidate solutions are checked against the original expression, including its domain restrictions. Unit-compatible equality alone does not determine physical validity or select the physically relevant root.

General results normally display 15 significant digits; closely spaced roots may use up to 17 digits to remain visually distinct. More displayed digits do not remove floating-point limitations. The calculator does not propagate uncertainty in measured inputs or CODATA constants.

## Interaction and History Checks

The acceptance workflow uses the actual app's WebKit editor, isolated example data, and native-window checks. It exercises result reuse, Scientific / Physics switching, repeated preview updates, long expressions, keyboard visibility, state snapshots, and local persistence. Each mode is tested with 100 and 250 history rows, including rejection of a 251st row without replacing the draft or other mode's records.

Both modes retain their loaded history editors between switches. Tests check editor reuse and preservation of drafts, units, bindings, language changes, and undo / redo isolation. Acceptance found and fixed a real Redo routing error after Undo restored a nonempty draft from a committed calculation; regressions also cover formula-library additions and later text edits. The first cold load still creates and calculates rows. A balanced 80-fraction expression (797 ASCII characters / 3186 LaTeX characters) exercises long input without weakening the independent parser-depth safety limit; an overly deep expression is rejected safely.

Automated timing measures synchronous JavaScript handling and a later rendering opportunity. It does not measure physical mouse click-to-paint latency or establish a performance guarantee on other machines.

At 250 rows in each mode, the final run recorded the following on the test host:

| Operation | Synchronous handling | To a later frame opportunity |
| --- | ---: | ---: |
| First Physics load | about 919 ms | about 1167 ms |
| Warm Scientific switches | 129–269 ms | 188–335 ms |
| Warm Physics switches | 473–667 ms | 519–770 ms |

The cache avoids repeated editor construction; it does not make full-history interaction instant. Significant pauses remain, including during warm Physics switches. This run does not establish a general speedup over prior versions.

For the first click on a background window, two different checks are kept separate: the native window's first-mouse acceptance policy, and one trusted coordinate-pointer click delivered to a visible background window. The latter changed the mode with one click. It did not reproduce or certify the entire human mouse-click-and-macOS-activation path.

## Distribution and Remaining Gaps

- The test host is an Apple Silicon / arm64 Mac running macOS 27.0. macOS 14 is the minimum build target, not an independently tested system. No Intel package is provided.
- A separate clean Mac, a physical macOS 14 device, and the full human first-click activation path remain unverified.
- The app is ad-hoc signed, not Developer ID signed or Apple notarized. ZIP integrity and bundle-signature checks do not substitute for publisher identity, Apple approval, or a clean Gatekeeper first-install test.
- Algebraic solving remains limited to supported real-scalar equations with one unknown. Arbitrary nonlinear or simultaneous equations, calculus, vectors, tensors, and complex physics solving are outside this scope. A formula-library scalar entry does not promise that every variable can be solved for.
- Dimension consistency is necessary, not sufficient. Model assumptions, shared-variable meaning, valid physical ranges, and root selection remain the user's responsibility. Temperature uses kelvin, without Celsius / Fahrenheit offset conversion.

Independently verify important calculations. When reporting a problem, include the expression, values and units, expected and actual results, app version, and macOS version. Public issue reports should not contain private history or sensitive screenshots.

2026-10-15 最终构建通过 202 项计算与回归测试、114 项真实 WebKit 检查、24 项原生交互和 31 项扩展验收，另有上表列明的原生窗口、布局、剪贴板和本机保存检查。202 项包含 50 项独立物理标准和 42 项边界 / 输入往返回归，128 项定向物理 / 公式检查不额外相加。包完整性、签名完整性、版本和 arm64 架构已核对。

本轮覆盖双模式各 100 / 250 行历史、结果复用、80 项分式组成的长算式和状态恢复。验收发现并修复了提交后撤销恢复非空草稿时，重做误走文本通道的真实问题。标准答案不从被测计算器的结果反推；数值之外，也检查单位、解数和错误状态。相对误差阈值是软件核对标准，不是测量不确定度或精度保证。

重点边界是漏负根、近重根误判、输入舍入、极小数下溢和系数消去。超出可靠范围时应明确拒绝，不把数值丢失包装成精确根或无解。有限的十进制核对不等于通用符号代数或任意精度；通常显示 15 位，近根必要时最多 17 位也不改变这一点。

模式切换复用已加载历史，但满历史仍有明显停顿。250 行时到下一次渲染机会：首次物理加载约 1167 毫秒，热切换科学 188–335 毫秒、物理 519–770 毫秒。这不等于人手点击到画面完成的时延，也不能证明所有场景比旧版更快。后台可信鼠标事件和原生首击策略分开验证，尚未完整认证人手首次点击并自动激活窗口的路径。

测试只覆盖当前 arm64、macOS 27.0 主机。macOS 14 只是最低构建目标，独立全新 Mac 首次安装仍未验证；应用没有 Developer ID 签名或 Apple 公证。包校验值见本版本发布说明。源码、私人记录和本机日志不公开。
